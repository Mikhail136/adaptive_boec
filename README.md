# Adaptive Boec / Адаптив-Боец

Инженерный демонстрационный проект для темы **«Сжатие потока информации»**.

Проект показывает MVP системы адаптивной приоритизации, сжатия и отбора сообщений
для перегруженного канала связи. Это учебно-демонстрационная модель: она не
использует секретные данные, не подключается к реальным системам связи и не
является боевой системой управления.

## Идея

В смешанном информационном потоке есть разные сообщения:

- координаты целей;
- команды;
- телеметрия БПЛА;
- видеокадры;
- сенсорные данные;
- сервисные сообщения.

Если канал ограничен, обычная отправка по порядку может занять полосу
второстепенными данными. **Адаптив-Боец** демонстрирует другой подход:

1. оценить важность каждого сообщения;
2. компактно упаковать телеметрию и координаты;
3. сжать текстовые/служебные данные;
4. убрать повторы низкоприоритетных сообщений;
5. проредить частую телеметрию;
6. отправить более важные сообщения первыми;
7. сравнить результат с базовой отправкой.

## Что уже реализовано

- `core/packet.py` — модель пакета и типы сообщений.
- `core/importance.py` — оценка важности сообщений.
- `core/compression.py` — zlib-сжатие полезной нагрузки.
- `core/deduplication.py` — дедупликация и агрегация телеметрии.
- `core/scheduler.py` — приоритетный планировщик.
- `core/metrics.py` — метрики доставки, критических сообщений и сжатия.
- `channel/emulator.py` — эмулятор ограниченного канала с отчётом о потерях.
- `adapters/mixed_stream_generator.py` — генератор смешанного потока.
- `adapters/telemetry_adapter.py` — бинарная упаковка координат и телеметрии.
- `experiments/run_demo.py` — основной демонстрационный сценарий.
- `tests/test_core_pipeline.py` — базовые автотесты MVP.

## Быстрый запуск

```bash
python experiments/run_demo.py
```

Пример с настройками:

```bash
python experiments/run_demo.py --count 100 --bandwidth 1800 --loss 0.05 --seed 42
```

Параметры:

- `--count` — число входных сообщений;
- `--bandwidth` — доступная полоса канала в байтах за цикл;
- `--loss` — вероятность случайной потери пакета от `0.0` до `1.0`;
- `--seed` — фиксирует случайность для воспроизводимого эксперимента.

## Архитектура MVP

```text
mixed stream generator
        |
        v
importance scorer
        |
        v
compression / telemetry packing
        |
        +------------------+
        | baseline channel |
        +------------------+
        |
        +--> adaptive pipeline:
             deduplication -> telemetry aggregation -> priority scheduling -> channel
```

## Метрики

Демонстрация считает:

- общее количество входных пакетов;
- количество доставленных пакетов;
- долю доставки;
- количество критических сообщений;
- долю доставки критических сообщений;
- сырой объём данных;
- переданный объём данных;
- коэффициент сжатия;
- загрузку канала;
- число сообщений, отброшенных из-за нехватки полосы;
- число случайно потерянных сообщений.

## Ограничения

Это демонстрационная инженерная модель. В текущем виде она не учитывает:

- криптографическую защиту;
- реальные радиопротоколы;
- задержки, очереди и подтверждения доставки;
- помехоустойчивое кодирование;
- распределённую работу нескольких узлов;
- реальное видео и потоковую передачу.

Эти ограничения сознательные: цель MVP — показать принцип адаптивного управления
потоком информации, а не имитировать полноценную систему связи.
